## 新增需求

### 需求:根目录启动脚本

项目根目录必须提供 `dev.sh` 可执行脚本,无参数运行时必须以 dev 模式同时拉起后端(uvicorn 监听 127.0.0.1:8000)与前端(vite dev server 监听 5173)。脚本必须在前台运行,`Ctrl+C`(SIGINT)或 SIGTERM 时必须同时终止后端与前端子进程,不得遗留孤儿进程。

脚本启动前必须执行预检查:
- 必须存在 `uv` 命令(后端运行时),缺失则打印安装提示并退出非 0
- 必须存在 `pnpm` 命令(前端运行时),缺失则打印安装提示并退出非 0
- 8000 端口被占用时必须打印提示(`lsof -i :8000` 输出)并退出非 0,不得尝试 kill 占用进程
- 5173 端口被占用时必须打印提示并退出非 0
- 根目录 `.env` 不存在时必须打印 warning(v0.1 后端可无 .env 启动,但实盘模块需要),不得退出

脚本必须从根目录运行后端(`uv run --project backend uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload`),让 pydantic-settings 从根目录读 `.env`。脚本必须从 `frontend/` 目录运行前端(`pnpm dev`)。脚本启动后必须打印访问 URL(`http://localhost:5173`)+ 后端 health URL(`http://127.0.0.1:8000/health`)+ 停止提示(`Ctrl+C`)。

#### 场景:正常启动
- **当** 开发者在项目根目录执行 `./dev.sh`,8000/5173 端口均空闲,uv/pnpm 已安装,根目录有 `.env`
- **那么** 脚本后台启动 uvicorn 与 vite,前台持续输出两个子进程的合并日志(带 `[backend]` / `[frontend]` 前缀),打印 `Web 工作台已启动: http://localhost:5173`,开发者浏览器访问 5173 看到首页

#### 场景:Ctrl+C 清理
- **当** 脚本运行中,开发者按 `Ctrl+C`
- **那么** 脚本捕获 SIGINT,向 uvicorn 与 vite 子进程发送 SIGTERM,等待最多 5s;若 5s 后子进程仍存活则发 SIGKILL,脚本退出码 0,无孤儿进程

#### 场景:端口占用
- **当** 8000 端口已被其他进程占用(如上次脚本异常退出未清理),开发者执行 `./dev.sh`
- **那么** 脚本打印 `错误: 端口 8000 被占用` + `lsof -i :8000` 输出 + 提示 `请先执行 ./dev-stop.sh 或手动 kill`,退出码 1,不启动任何子进程

#### 场景:工具缺失
- **当** 开发者环境无 `uv` 命令,执行 `./dev.sh`
- **那么** 脚本打印 `错误: 未找到 uv,请先安装: https://docs.astral.sh/uv/`,退出码 1,不启动任何子进程

#### 场景:无 .env 警告
- **当** 根目录无 `.env` 文件,开发者执行 `./dev.sh`
- **那么** 脚本打印 `警告: 未找到 .env 文件,实盘交易功能将不可用,回测/进化可正常使用`,继续启动后端与前端

### 需求:停止脚本

项目根目录必须提供 `dev-stop.sh` 可执行脚本,用于兜底停止 8000/5173 端口上的进程(当 `dev.sh` 异常退出未清理时)。脚本无参数运行时必须:
- 用 `lsof -ti :8000` 与 `lsof -ti :5173` 拿到占用端口的 PID 列表
- 对每个 PID 发送 SIGTERM,等待 3s
- 仍存活的发 SIGKILL
- 打印每个被停止的 PID 与端口;无占用时打印 `端口 8000/5173 均空闲`

#### 场景:正常停止
- **当** uvicorn(PID 12345)与 vite(PID 12346)运行中,开发者执行 `./dev-stop.sh`
- **那么** 脚本向 12345 / 12346 发 SIGTERM,等待 3s 内退出,打印 `停止端口 8000 上的进程: 12345` 与 `停止端口 5173 上的进程: 12346`,退出码 0

#### 场景:无占用
- **当** 8000/5173 端口均空闲,开发者执行 `./dev-stop.sh`
- **那么** 脚本打印 `端口 8000/5173 均空闲`,退出码 0

#### 场景:强制 kill
- **当** 端口 8000 上的进程(PID 12345)忽略 SIGTERM 3s 未退出
- **那么** 脚本向 12345 发 SIGKILL,打印 `强制 kill 端口 8000 上的进程: 12345`

### 需求:README Web 工作台章节

`README.md` 必须在「概述」之后、「快速开始」之前新增「Web 工作台(v0.1)」章节,内容必须包含:
- 一句话定位:单机本地量化工作台,浏览器访问,无鉴权,4 模块(策略管理 / 回测可视化 / 实盘监控 / 参数调优)
- 前置条件:已 `uv sync`(根环境,实盘模块依赖)+ `cd backend && uv sync` + `cd frontend && pnpm install`
- 启动命令:`./dev.sh`
- 访问地址:`http://localhost:5173`
- 停止方式:`Ctrl+C` 或 `./dev-stop.sh`
- 已知限制:单机 / 无鉴权 / 回测结果不持久化 / 实盘进程依赖根环境 torch(arm64 macOS 装不上)
- 原「快速开始」章节必须保留,标题改为「命令行模式(原 v0.0 工作流)」,内容不动

#### 场景:首次使用者
- **当** 开发者克隆仓库后读 README
- **那么** 「Web 工作台(v0.1)」章节在「概述」之后立即出现,告诉开发者前置条件 + `./dev.sh` 启动 + 5173 访问,开发者按章节执行可成功打开工作台

#### 场景:命令行用户
- **当** 开发者想用原命令行模式(search_eth_optimal.py / live_*.py / backtest_quant.py)
- **那么** 「命令行模式(原 v0.0 工作流)」章节仍在 README 中,内容与 v0.0 一致,开发者可直接使用

### 需求:脚本可执行权限

`dev.sh` 与 `dev-stop.sh` 创建后必须设置可执行权限(`chmod +x`),git 提交时必须保留可执行位(`git update-index --chmod=+x` 或 `git add` 后 verify mode 100755)。

#### 场景:克隆后直接执行
- **当** 开发者克隆仓库后立即执行 `./dev.sh`
- **那么** 脚本可执行权限已设置,无需手动 `chmod +x`,直接运行成功
